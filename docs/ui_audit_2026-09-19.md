# Phone and laptop UI audit (2026-09-19)

Two field reports from the first successful waypoint run triggered this audit: on the laptop the HOLD TO GO button vanished under the operator's pointer the moment nav started, and on the phone the control panel covered the whole map. A read-only audit of the five web pages (`oak_viewer.py`, `teleop.py`, `waypoint_nav_ui.py`, `property_map.py`, `calibration_wizard.py`) produced the findings below. Each finding has a GitHub issue; the numbers are in section 3.

## 1. Findings, by priority

P0 = safety, P1 = blocks field use, P2 = usability, P3 = polish. Line numbers refer to `pi_app/web/waypoint_nav_ui.py` unless stated.

1. P0. STOP disappears with the sheet. `btnStop`, `btnGo`, `btnPause` and `btnSkip` live inside `.sheet-body` (397–431), which is hidden in the collapsed state (140–141). Collapsing the sheet to see the map removes the only STOP control on the page. `teleop.py` does this right: its E-STOP is a fixed, always-visible 62 px control outside any collapsible container (1460–1467, 1603–1610). Fix: move STOP (and the nav status) to the always-visible status row or the toolbar.
2. P0. Nothing collapses the sheet when nav starts. `isNavigating` flips on the SSE tick (993) with no sheet reaction; the only `classList` writes are in the drag handler (2081–2116). Fix: force the collapsed state when nav starts, so the map and the robot are visible during a run.
3. P0. HOLD TO GO release semantics are undefined after launch. `goDown` (1822) fires `startNav()` when the fill reaches 100 percent, before the finger lifts; `goUp` (1842) only resets the fill. The button is hidden and STOP shown on the next telemetry tick (`updateGoButton`, 1748–1771), abruptly and decoupled from the gesture. "Hold to go" implies a deadman; nothing ties release to stop. Fix: a transition on the swap, a toast "Robot is moving — releasing does NOT stop it; use STOP", and STOP visible before the swap (finding 1).
4. P0. A native `confirm()` can open while the finger is still down, and the common trigger is a GPS-gate mismatch. `startNavWithWaypoints` (1851–1864) calls `confirm()` at 1861 for any validation warning, synchronously inside the hold timer. The JS gate at 1784 disables GO only for `gpsFix < 4`, so RTK float (5) passes as a soft warning, while the backend requires exactly 4 (`waypoint_nav.py:184–194`). Fix: gate on `gpsFix !== 4` in JS; move validation before the hold starts; never block inside the hold.
5. P0. The phone sheet's default state hides the map. The page loads in `half` (384); `half` and `full` share `max-height: 85vh` (107–113) and both show the body (140–144). On an iPhone viewport (660–850 px) minus the fixed toolbar (79) and GPS badge (97), about 100 px of map remain. Fix: default to collapsed; give `half` its own smaller height (about 40 vh) with the map visible.
6. P1. The sheet handle gives no live feedback. `onMove` is a no-op (2093); the state snaps only on release by a flat ±40 px threshold (2098–2115). Fix: drive the sheet transform from the pointer delta, snap on release, and make a tap on the handle toggle.
7. P1. No visible interlock between the teleop page and the nav page. Neither page checks the other's state; arbitration lives in the control loop. Confirm server-side that an armed teleop session cannot fight an active mission, and show which one owns the robot on both pages.
8. P1. The phone teleop deadman trips when the tab is backgrounded (250 ms heartbeat, `teleop.py:73`), for example when the operator switches to the nav page. The trip is now logged at WARNING but the UI shows only a lock. Fix: an explicit "deadman tripped: tab was hidden" message with a re-ARM control, and a `visibilitychange` handler that neutralizes intent before the trip.
9. P2. Destructive and safe actions look identical (433–460): Clear All, Reverse Route, Simplify and Center Robot share one style; Reverse Route acts on one tap (1250–1257). Fix: color-code destructive actions; confirm Reverse Route in-page.
10. P2. Small touch targets in the waypoint list: delete 28 px (166), drag 24 px (173), more 24 px (181). Fix: at least 44 px.
11. P2. Dashboard MJPEG streams keep running when the tab is hidden (`oak_viewer.py:286, 291`, 10 fps at 2007); no `visibilitychange` handler. Fix: blank the stream sources when hidden.
12. P3. `property_map.py` ignores safe-area insets (fixed bars at 248, 277, 285). Fix: `env(safe-area-inset-top)`.
13. P3. Field-critical numbers are small: `.route-metric .k` 9 px (254), `.wp-coords` 11 px (158). Fix: at least 12–13 px.
